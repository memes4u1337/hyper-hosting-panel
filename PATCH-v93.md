# HYPER-HOST v93 — страница «Базы данных»

powered by memes4u1337

Патч кумулятивный: включает всё из v92 (вёрстка дашборда и FTP, реальная телеметрия ботов, SSL на www) плюс полностью переделанную страницу баз.

```bash
sudo ./apply-v93-databases-ui.sh
```

После установки — **Ctrl+F5**, стили подписаны `?v=93`. Версия внизу сайдбара: **1.9-v93**.

---

## Что было сломано

**1. Раскладка ломалась на уровне сетки.** `.db-layout-v24` — это `grid-template-columns: 360px minmax(0,1fr)`. Внутрь PHP клал два прямых потомка: `<section class="db-top panel-card">` с блоком статусов MariaDB и `<div class="row g-4">` со всем остальным. Grid раскидывал их по колонкам — вся шапка со статусами уезжала в узкие 360px и там сминалась. Плюс `.db-top` сам был `display:flex`, что доламывало остатки.

**2. Подписи слипались со значениями.** У `.db-row-card > div` не было ни одного правила. Разметка `<span>База</span><b>hyper_host_bot</b><small>Локально</small>` рендерилась инлайном подряд — получалось «Базаhyper_host_botЛокально». То же самое во всех карточках баз, аккаунтов и заданий импорта.

**3. Bootstrap бился с grid.** `row g-4` с детьми `col-xl-4` / `col-xl-8` находился внутри grid-ячейки — ровно та же болезнь, что была на странице FTP.

**4. Переключатель «Локально / Внешний вход»** был голыми радиокнопками без стилей.

## Что стало

**Своя сетка вместо конфликта.** `.db-page-v93` — вертикальный поток: шапка на всю ширину, под ней `.db-columns-v93` (390px + остальное). Никакого bootstrap `row/col`, никаких вложенных grid поверх flex. На узких экранах схлопывается в одну колонку.

**Шапка.** Заголовок с описанием, кнопки действий справа, под ними сетка из 8 статус-плиток: сервер, порт 3306, режим доступа, SQL host, служебная база pma, лимит импорта, память экспорта, счётчики. Каждая плитка — подпись сверху мелким uppercase, значение снизу моноширинным. Проблема от `mysql-doctor-json` выводится отдельной янтарной плашкой, а не блёклым bootstrap-алертом.

**Карточка базы.** Иконка, имя, хост-паттерн, справа бейдж «только локально» (зелёный) или «внешний вход» (янтарный) — и цветная полоса слева в тон. Ниже сетка полей: пользователь, хост подключения, порт, пароль. **Клик по любому моноширинному значению копирует его** — на секунду подсвечивается зелёным и пишет «скопировано». Кнопка «Все данные» копирует готовый блок с Host/Port/Database/User/Password.

**Карточка импорта.** Полноширинная полоса прогресса (зелёная при успехе, красная при ошибке), под ней шесть плиток: прогресс, прочитано из скольких, скорость и жив ли процесс, таблиц создано и размер базы, прошло и сколько осталось, ID задания. Ошибка — красная плашка с полным текстом, а не обрезанный `title` при наведении. Подсказка про «MySQL занят обработкой блока» — отдельная синяя плашка.

**Переключатель доступа** стал сегментированным контролем: две равные кнопки, выбранная подсвечивается синим, есть hover и видимый focus для клавиатуры.

**Формы** получили подписи над полями вместо placeholder-ов, которые исчезают при вводе.

**Пустые состояния** — не голый текст, а пунктирная рамка с подсказкой, что делать: «Баз пока нет. Создай первую в форме слева.»

## Файлы

| Файл | Куда |
|---|---|
| `src/public/index.php` | `/var/www/hyper-host/public/index.php` |
| `src/public/assets/style.css` | `/var/www/hyper-host/public/assets/style.css` |
| `src/public/assets/app.js` | `/var/www/hyper-host/public/assets/app.js` |
| `scripts/hhctl` | `/usr/local/sbin/hyper-host-ctl` |

Бэкап пишется в `/opt/hyper-host/backups/`, при любой ошибке скрипт откатывается сам. Перед установкой прогоняются `bash -n` и `php -l`.

Если обновляешься через git — твой обычный блок работает как есть, `install.sh` увидит установленную панель и разложит файлы из `src/`.
